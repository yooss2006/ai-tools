# README Profile

## Purpose

Help a repository visitor quickly understand what the project does, why it is useful, and how to get started. A README is an entry point, not a dumping ground for every project detail.

## Use when

- documenting a repository or package entry page;
- giving new users/contributors the shortest path to understand and run the project;
- linking outward to deeper documentation.

## Default structure

```markdown
# Project name

[What it does + why it matters]

## Key capabilities  <!-- optional -->

## Getting started

### Prerequisites
### Install / setup
### Run / basic usage

## Documentation  <!-- links to deeper docs -->

## Contributing  <!-- when relevant -->

## Support / maintainers  <!-- when relevant -->

## License  <!-- when applicable -->
```

## Primary / secondary types

- Primary: Learning (for getting started) or Explanation (for project overview), depending on the repository.
- Common secondary: Reference for commands/configuration links.

## Quality checks

- A new visitor can explain the project after the opening section.
- The quick-start path is short and executable.
- Long architecture/reference material is linked instead of duplicated.
- Internal repository links are relative when practical.
- The README does not claim to be complete documentation when deeper docs exist.

## Notes

GitHub describes repository READMEs as a place to explain what a project does, why it is useful, how to get started, where to get help, and who maintains/contributes to it. Use those as prompts, not mandatory sections for every repository.
