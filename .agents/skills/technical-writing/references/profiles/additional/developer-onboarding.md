# Developer Onboarding Profile

## Purpose

Help a new contributor become productive in a project by moving from access/setup to understanding the system and completing a first meaningful development workflow.

## Default structure

```markdown
# Developer onboarding

## What you will be able to do

## Required access and prerequisites

## Local environment setup

## Run and verify the project

## Project structure and key concepts

## Development workflow

## Tests / quality gates

## Make your first change

## Troubleshooting

## Where to ask for help / ownership
```

## Primary / secondary types

- Primary: Learning
- Common secondary: Reference and Problem solving

## Guidance

- Put access blockers and prerequisites before local setup.
- Prefer a short verified “first success” path over explaining the whole architecture up front.
- Link to architecture/reference docs instead of duplicating them.
- Use the project's actual commands, paths, terminology, and contribution workflow.
- Make support/ownership discoverable so blocked newcomers know where to go.

## Quality checks

- A new contributor can verify the environment works.
- The guide does not assume undocumented credentials or tribal knowledge.
- The first-change path exercises the normal development workflow.
- Deep reference material is linked rather than copied.
